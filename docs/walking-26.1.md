# Ходьба Minecraft 26.1 и 26.2

Расчёты в `src/vanilla-walking.js` сверены с байткодом официального клиента **26.1**.
Клиент получен через [официальный манифест Mojang](https://piston-meta.mojang.com/mc/game/version_manifest_v2.json),
SHA-1 файла `191771837687b766537a8c4607cb6fad79c533a1` проверен перед разбором.
JAR и извлечённые классы находятся только во временной папке машины; в проект они не включены.
Разбор выполнен через `javap -c -p`, сам клиент Minecraft не запускался.
Для ветки **26.2** тем же способом разобран локальный клиент PrismLauncher
`libraries/com/mojang/minecraft/26.2/minecraft-26.2-client.jar`,
SHA-1 `2dc72797acbc1b63fc16a11c4ac393605f453754`.

Сверенные методы:

| Класс | Методы / назначение |
| --- | --- |
| `KeyboardInput`, `Vec2` | Нормализация клавиш, операции с `float` |
| `LocalPlayer` | `modifyInput`, `modifyInputSpeedForSquareMovement`, `distanceToUnitSquare`, замедление использования предмета |
| `Entity` | `getInputVector`, `move`, `collide`, `collectCandidateStepUpHeights`, `getOnPos`, `checkSupportingBlock` |
| `LivingEntity` | `travelInAir`, `getFrictionInfluencedSpeed`, `jumpFromGround`, `getJumpPower`, `getJumpBoostPower` |
| `Player` | `getFlyingSpeed`, `maybeBackOffFromEdge`, `isAboveGround`, `canFallAtLeast` |
| `Direction`, `Mth` | `axisStepOrder`, таблица `sin`/`cos`, `equal(double, double)` |
| `CollisionGetter` | `findSupportingBlock`: расстояние до центра и порядок выбора при равенстве |
| `UseEffects` | Значения по умолчанию для замедления и разрешения спринта |

Реализация выбирается по согласованной версии протокола: 26.1 или 26.2. Это работает и при настройке
«авто». В первоначальном варианте ветка 26.2 оставалась на старой физике Prismarine: исправления
для 26.1 там не применялись. Теперь для 26.2 предусмотрены отдельные формулы, а активная ветка
выводится в лог при появлении в мире. Неизвестные версии остаются на Prismarine с явной отметкой в логе.

## Изменения

- Ввод: нормализация клавиш, множитель `0.98f`, приседание, использование предмета и преобразование
  диагонального ввода. Промежуточные операции округляются через `Math.fround` в местах Java `float`.
- Ускорение на земле использует `speed * (0.21600002f / friction³)` с нужным порядком округлений.
  Трение после движения также вычисляется как `float`; воздушное ускорение спринта — `0.025999999f`.
- В 26.2 `friction_modifier` и `air_drag_modifier` меняют коэффициенты через
  `clamp(1f - (1f - base) * modifier, 0f, 1f)`. Модификатор сопротивления воздуха влияет и на
  вертикальное движение. При итоговом трении не больше `0.6d` ускорение равно `getSpeed()`;
  в этой ветке нет деления на куб коэффициента. В 26.1 сохранена его исходная формула.
- Поворот вектора ввода и импульс спринт-прыжка используют таблицу из 65536 значений, как `Mth`.
  Угол совпадает с непрерывным углом отправляемого пакета, включая переходы через полный оборот.
- Прыжок учитывает `jump_strength`, округление Jump Boost и сохраняет большую текущую вертикальную скорость.
- Столкновения: сначала Y, затем большая по модулю горизонтальная компонента. Для подъёма выбираются
  высоты граней препятствий в пределах `step_height`; проверяются препятствия над головой.
- Горизонтальный флаг столкновения и сброс скорости используют допуск ванильного `Mth.equal`.
  Незначительное округление не должно создавать ложную стену и выключать спринт.
- Трение выбирается с учётом поддерживающего блока, включая нависание центра игрока над краем.
  При приседании проверяется реальное пересечение опоры под ногами; движение к краю уменьшается шагами `0.05`.
- Состояние опоры хранится отдельно в прогнозах pathfinder, переносится в бота после применённого тика
  и сбрасывается при телепортации/респавне. Атрибуты сервера не изменяются прогнозами.

Патч `scripts/patch-physics.js` применяется при старте и после установки зависимостей. Он сохраняет
старые ветки для других версий и проверяет ожидаемые участки исходника перед записью. При обновлении
`prismarine-physics` несовместимый исходник должен вызвать явную ошибку, а не частичную замену.

## Проверка

`npm test` сравнивает установленную физику Mineflayer с `test/reference/walking-26.1.json`
и `test/reference/walking-26.2.json`. По десять сценариев для каждой версии включают ходьбу, диагонали, спринт, приседание, лёд/синий лёд, серверную скорость,
использование предмета, прыжок и Jump Boost. Каждый длится 60 тиков, последние 20 — без ввода.
Ещё три сценария 26.2 проверяют изменённое трение, сопротивление воздуха в прыжке и коэффициент,
обрезанный до нуля. Всего 23 траектории.
На контрольных тиках координаты и скорости сравниваются с допуском `1e-10`.

Числа получены отдельной программой `test/reference/WalkingReference.java`, написанной по сверенным
формулам. Это независимая проверка арифметики Java/JavaScript, **не запись работы запущенного клиента**.
Для пересоздания эталона с установленным JDK:

```powershell
javac -d $env:TEMP test/reference/WalkingReference.java
java -cp $env:TEMP WalkingReference
java -cp $env:TEMP WalkingReference 26.2
```

Вывод команд `java` — JSON для соответствующих эталонных файлов. Штатным тестам Java не нужна.

Отдельные регрессии проверяют оба порядка столкновений X/Z, подъём на плиту с земли и при приземлении,
низкий потолок, край при приседании, опору на льду, толстый снег над льдом, замедление предметом,
реальные маршруты `.goto`/`.follow`, остановку, телепортации и плавные повороты головы.
`npm run test:integration` проверяет выбор версии и физики в режиме «авто», пакеты и команды
через локальные серверы 26.1/26.2, включая ранее исправленное ломание блоков. Также воспроизводится
серия коррекций во время движения: ввод останавливается, диагностический файл содержит
действительно отправленные пакеты после преобразований адаптера.

При четырёх коррекциях за три секунды с активным вводом `src/movement-recovery.js` прекращает
текущую задачу и удержание клавиш. Скорость и позицию он не изменяет. Автоматического возобновления нет.
В `data/movement/<id>.json` сохраняются до 400 последних записей состояния, пакетов движения
и коррекций. В файле нет пакетов авторизации, сообщений чата и инвентаря. Запись асинхронная;
новый отчёт данного бота заменяет прежний. Сам факт коррекции не устанавливает её причину:
серия коротких серверных телепортаций при активном вводе тоже может остановить маршрут.

## Вторая сверка (байткод клиента 26.2)

Сверены `LivingEntity.aiStep`, `travel`, `travelInAir`, `handleRelativeFrictionAndCalculateMovement`,
`Entity.move`, `getBlockSpeedFactor`, `getBlockJumpFactor`, `getEffectiveGravity`, `Entity.turn`,
`LocalPlayer.aiStep` (спринт), `isInShallowWater`. Порядок тика (порог скорости → прыжок с `noJumpDelay`
→ ввод → движение → гравитация → трение) у бота совпадает. Исправлены расхождения:

- спринт держится без Ctrl, пока зажат W; прекращается без W, при ударе в стену, при еде ≤ 6
  и в мелкой воде (голова над водой). Присед не даёт начать спринт, но не прерывает начатый;
- замедление песка душ/мёда (×0,4) и прыжок с мёда (×0,5), с атрибутом `movement_efficiency`;
- гравитация из атрибута `minecraft:gravity`, медленное падение ограничивает её 0,01; над
  незагруженным чанком вертикальная скорость −0,1 вместо гравитации;
- лодки, вагонетки и шалкеры — твёрдые (на лодку можно подняться, как на ступеньку);
- ягодный куст замедляет (0,8; 0,75; 0,8), как паутина;
- позиция не меняется, если после столкновений сдвиг меньше 1e‑7, а потеряно больше.

## Границы проверки

Это перенос проверенных частей наземного движения, а не всего движка Minecraft.
Плавание, элитра, транспорт, смена позы/ползание, движущиеся поршни, порошковый снег, отскок от
кровати, выталкивание из блока (`moveTowardsClosestSpace`), граница мира и часть эффектов
по-прежнему зависят от возможностей Prismarine.
Формы блоков берутся из его данных. Полного сравнения этих режимов с ванильным клиентом здесь нет.
Тестовые серверы не содержат Grim; отсутствие флагов на конкретном внешнем сервере не подтверждено.

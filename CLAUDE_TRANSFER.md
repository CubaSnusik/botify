## Что пользователь заказал

Команда: `.transfer <предмет> <ник бота-покупателя>`, например:

```text
.transfer spruce_log Dan13lCBT
```

Один бот создаёт ордер на сумму выбранного предмета у остальных подключённых ботов на том же сервере. Все эти боты по очереди сдают предметы в его ордер. Текущие фермы участников надо остановить, чтобы они не выбросили продаваемые брёвна и не конфликтовали с GUI.

Пользователь разрешил небольшую произвольную цену, например 5.0 или 5.6; реализован случайный выбор 5.0–5.9 за штуку. Количество — сумма предметов у продавцов после остановки их предыдущих задач. Покупатель должен иметь деньги; возможен серверный налог.

Каждый продавец сначала сдаёт **ровно 1 предмет**. Только после точного сообщения покупателю можно сдавать остаток. Переносить стаки медленно, из случайных слотов. Реализованы паузы 300–700 мс между действиями; пользователь ранее требовал минимум 200 мс для инвентарных операций.

`.stop` у любого участника отменяет общую операцию. После ошибки нет автоматического повтора или возобновления фермы. Уже созданный ордер может остаться открытым; это явно сообщается в логе. Автоматическое извлечение купленного из Your Orders не реализовано и отдельно не запрашивалось.

## Подтверждённая последовательность серверных экранов

### Покупатель

1. Отправить `/order`.
2. В обычном окне `Orders (Page 1)` нажать `Your Orders` (в предоставленном логе слот 51, предмет chest). Искать по смыслу, не фиксировать этот номер.
3. Окно `Orders -> Your Orders`. Каждый свободный слот представлен отдельной одинаковой кнопкой:
   - имя `New Order`;
   - предмет `gray_stained_glass_pane`;
   - lore `Click to create new order`.
   В реальном логе свободны слоты 0–17. Слоты 18–44 — `Max Orders`, красные панели, lore `Buy Donut+ for more order slots`; их нажимать нельзя.
4. После клика свободного слота приходит **custom dialog**, не обычный инвентарь: `Choose Item`. Есть текстовое поле `Search`, кнопка `Search`, кнопки предметов, например `Spruce Log`.
5. `How many?`: поле `Amount`, кнопка `Next`.
6. `Price per item?`: поле `Price`, кнопка `Review Order`.
7. `Review Order`: текст `Item: Spruce Log`, `Amount: ...`, `Price: $ ... each`, `Total: ...` с налогом. Кнопки Cancel, Change Item, Change Amount, Change Price, **Create Order**.
8. Перед Create Order обязательно сверить предмет, количество и цену с ожидаемыми.

### Продавец

1. Отправить `/order spruce_log` для фильтра по предмету.
2. Найти hopper `Filter`, переключить на **Recently Listed**.
3. Просматривать объявления, следующая страница — arrow с названием `Next page`. Не полагаться на номер или сторону кнопки.
4. Пример lore объявления: `$ 5.6 each`, `0/73 Delivered`, `Click to deliver items`. Имя владельца на присланных скриншотах не показано. Код проверяет item ID, цену, общий объём, уже доставленное количество; если есть явный owner/buyer, проверяет и его. При нескольких совпадениях на странице останавливается. Пробная сдача нужна именно для подтверждения получателя, поскольку этих признаков недостаточно для абсолютной идентификации.
5. Клик объявления открывает `Orders -> Deliver Items` — пустое окно на 36 контейнерных слотов (4 ряда).
6. Положить предметы. Для пробы — один, а не стак. Остаток стека вернуть с курсора в инвентарь.
7. **Нажать Escape**, то есть вызвать `bot.closeWindow(window)`. Именно закрытие переводит на следующий экран.
8. `Orders -> Confirm Delivery` — 27 слотов: красная панель отмены, предмет по центру, зелёная панель подтверждения. Код ищет единственную lime/green stained glass pane и проверяет наличие ожидаемого предмета.
9. Подтвердить. Покупателю приходит точное серверное сообщение:

```text
KindaStraw98559 delivered you 1 Spruce Log
```

`You ordered 1 Spruce Log` — другое сообщение, оно не подтверждает доставку! Проверка receipt требует точного ника продавца, количества и названия предмета, не принимает цитату игрока в чате. Реализован таймаут 15 секунд; подписка ставится перед кликом подтверждения.

10. После успешной пробы снова найти ордер и сдать остаток продавца. Координатор обновляет ожидаемое число Delivered. Для массовой сдачи также ждёт сообщение с точным количеством. Формат реального сообщения о массовой сдаче пока не проверен.

## API и особенности проекта

- `BotManager.bots` — Map экземпляров BotInstance; у экземпляра `.bot`, `.acc.username`, `.state`, `.server()`, `.manager`, `.task`.
- `runTask()` теперь сохраняет Promise в `task.done`. Transfer останавливает старые задачи, ждёт завершения, назначает всем участникам общий AbortController и отслеживает смену соединения/задачи.
- `src/screens.js`: `windowView`, `itemView`, обработка custom dialogs. `inst.dialogClick(index, values)` отправляет действие диалога. `inst.dialog` содержит title/body/inputs/buttons/seq/waiting.
- Окно Mineflayer: `window.items()` — предметы игрока, `window.containerItems()` — предметы контейнера, `selectedItem` — курсор. Метода `inventoryItems()` здесь нет.
- `bot.clickWindow` локально предсказывает изменения. Кроме того, после копания библиотека может задержать клик хотбара примерно на 500 мс. Перед кликами код ждёт этот период и перепроверяет окно.
- `src/auto-tree-farm.js` и тесты `test/supply-transfer.test.js`, `test/auto-tree-farm.test.js` содержат уже отлаженные примеры работы с окнами и серверными коррекциями. Не ломать их при исправлении transfer.
- Зависимости имеют локальные патчи в `scripts/patch-*.js`, применяемые postinstall. Не заменять версии/патчи вслепую.
- Секреты аккаунтов и Discord находятся в игнорируемом `data/`. Не печатать и не коммитить их.

# Botify

Менеджер headless-ботов для Minecraft Java (до **26.2** включительно). Монохромный десктоп-интерфейс:
список ботов, консоль у каждого, общая консоль на всех, инвентарь с иконками, ответы на экраны сервера,
управление поворотом и зажатием кнопок.

Боты ведут себя как обычный клиент: ходят по физике, ломают только то, что видят и до чего дотягиваются,
и шлют серверу те же пакеты в том же порядке, что и игра.

## Запуск

```
npm install        # один раз: докачает Electron и данные для 26.2, применит патчи зависимостей
npm start          # десктоп-окно
npm run web        # то же самое в браузере: http://127.0.0.1:7878
```

Или двойной клик по `Botify.cmd` (при первом запуске сам сделает `npm install`).

Нужен Node.js 20+. Если порт 7878 занят, бэкенд возьмёт свободный.

## Добавление ботов

Кнопка **«Добавить ботов»** внизу сайдбара, три вкладки:

| Вкладка   | Что это |
|-----------|---------|
| Оффлайн   | Просто ники, для серверов с `online-mode=false`. Есть генератор `Bot_01…Bot_NN`. |
| Microsoft | Официальный вход по коду: открываешь microsoft.com/link, вводишь код. Пароль Botify не видит. |
| Токены    | По одному на строку, тип определяется сам (см. ниже). Перед сохранением каждый токен проверяется у Mojang. |

Форматы токенов:

| Строка | Что это |
|---|---|
| `eyJ…` | Minecraft access token (JWT). Живёт ~24 ч, потом нужен новый. |
| `M.C…` | Microsoft refresh token. Обновляется сам, новый refresh записывается обратно. Подходящий client_id подбирается из стандартных. |
| `M.C…\|client_id` | refresh token со своим client_id (если он выдан другим приложением). |
| `{"accessToken": "…", "refreshToken": "…"}` | JSON-строка (экспорт лаунчеров и менеджеров аккаунтов). |

### Сервер

У каждого бота либо **глобальный** сервер (из настроек), либо **свой**: можно держать одного бота на одном сервере,
другого на другом. Адрес пишется одной строкой: `mc.example.com` или `1.2.3.4:25570`. Без порта будет 25565
или SRV-запись домена, как в обычном клиенте (`hypixel.net` → `mc.hypixel.net:25565`). В handshake уходит
введённый адрес. Версия — «Авто» (бот спрашивает сервер) или конкретная.

## Интерфейс

**Сайдбар:** голова скина, ник, сервер и здоровье, точка статуса (онлайн / подключение / оффлайн / ошибка).
Если у бота открыт диалог или меню, это видно под ником. Правый клик по боту открывает меню, при наведении
появляется кнопка питания.

**Страница бота:**
- консоль: чат сервера, ответы на команды и экшн-бар (строка над хотбаром). Повторы экшн-бара, где меняются
  только цифры (таймеры, счётчики), не пишутся;
- статус: здоровье, голод, координаты (клик копирует), измерение, режим, пинг, последний экшн-бар;
- инвентарь с иконками, прочностью, именами и описаниями предметов;
- действия: «идти к X Y Z», быстрые кнопки, зажатие кнопок;
- поворот головы;
- карточки экранов сервера, когда они открыты.

**Инвентарь** работает как в игре:
- предметы перетаскиваются мышкой, перетащил в зону снизу — выбросил;
- `Shift`+клик быстро перекидывает стак между хотбаром и инвентарём;
- наведи на слот и жми `1`–`9`, чтобы положить предмет в хотбар; `Q` выбрасывает 1 предмет, `Ctrl+Q` — стак;
- колёсико над хотбаром меняет выбранный слот;
- ПКМ по предмету открывает меню: положить в слот 1–9 и взять, взять в руку, в левую руку, надеть, выбросить.

**Зажатие кнопок:** переключатели ЛКМ, ПКМ, W, Shift, Пробел, Спринт; зажатая подсвечивается.
- ЛКМ ломает блок под прицелом. Если бота повернуть, переключается на новый блок. Сущность под прицелом бьёт с кулдауном.
- ПКМ держит еду, щит или лук, либо ставит блоки и жмёт кнопки раз в 4 тика, как ванильный клиент.

**Поворот головы:** компас (север сверху, тяни стрелку), ползунок наклона, поля yaw/pitch в градусах как в F3,
кнопки С/В/Ю/З, ±45°, Вверх/Прямо/Вниз. По этим командам бот поворачивается плавно, за несколько тиков.

**Экраны сервера:** когда сервер что-то показывает боту, сверху справа появляется карточка, а в консоль пишется
содержимое и подсказка, как ответить.
- **Диалоги** (1.21.6+): подтверждения, кнопки, анкеты с полями (текст, переключатель, список, ползунок).
  Кнопки работают как в игре: выполняют команду, подставляют поля в шаблон или отправляют серверу ответ с полями.
- **Меню-сундуки** (например `/tpaccept`, где надо нажать зелёное стекло): сетка слотов с иконками,
  в тултипе имя и описание предмета. Клик — ЛКМ, правый клик — ПКМ, `Shift`+клик.
  В консоли серые стёкла-заполнители скрываются, остаются только кнопки.

**Общая консоль:** команда уходит всем выбранным справа ботам, если никто не выбран — всем онлайн.
Там же «Идти всем», слоты 1–9, зажатие кнопок и «Поворот всем».

**Горячие клавиши:**

| Клавиши | Что делают |
|---|---|
| `Ctrl+K` | поиск ботов |
| `Ctrl+↑` / `Ctrl+↓` | предыдущий / следующий бот |
| `/` | фокус в консоль |
| `Tab` | дополнить команду |
| `↑` / `↓` в консоли | история |
| `Esc` | закрыть меню или окно |

Аккаунты входят по очереди: следующий начинает подключение после появления предыдущего в мире
или завершения его неудачного входа. Между попытками выдерживается настроенная пауза входа.
Очередь общая для кнопок, команд и автопереподключений; ожидающие аккаунты показываются «в очереди».
Отключение ожидающего аккаунта отменяет его вход; «отключить всех» отменяет оставшуюся очередь.

При кике `You are already online` только этот аккаунт получает сохранённую отметку
`! Утерян / украден` с исходной причиной. Его автопереподключения останавливаются,
а массовый запуск пропускает его и продолжает остальные аккаунты. Это обозначение ответа
сервера об уже активной сессии. Возобновить вход можно, нажав «Снять отметку» в карточке аккаунта,
а затем «Подключить».

**Настройки** (шестерёнка внизу): глобальный сервер и версия, автопереподключение с нарастающей паузой,
интервал входа при «подключить всех», дальность прорисовки, тёмная/светлая тема.

## Консоль

Текст без точки уходит в чат сервера (`/команды` тоже). Команды Botify начинаются с точки.

| Команда | Что делает |
|---|---|
| `.goto <x> [y] <z>` / `.goto <ник>` | дойти пешком, `~` = относительно (`.goto ~10 ~ ~-5`) |
| `.follow <ник> [дист] [spin] [speed=град/с]` | следовать за игроком; по умолчанию 2 блока; `spin` — вращаться и выбирать W/A/S/D по текущему углу; скорость 1–720°/с, по умолчанию 120; `.stop` — остановить |
| `.circle <ник> [радиус] [spin] [speed=град/с]` | ходить вокруг игрока; радиус по умолчанию 3 блока, минимум 1; `spin` и скорость вращения — как у `.follow`; `.stop` — остановить |
| `.stop` | остановить всё и отпустить зажатые кнопки |
| `.break [x y z]` | сломать блок (без координат — тот, на который смотрит) |
| `.mine <блок> [кол-во]` | найти и добыть блоки поблизости |
| `.slot <1-9> [предмет]` | выбрать слот хотбара; с предметом — сначала положить его туда (`.slot 2 pickaxe`) |
| `.hold <lmb\|rmb\|w\|a\|s\|d\|jump\|sneak\|sprint>` | зажать кнопку |
| `.release [кнопка]` | отпустить (без аргумента — всё) |
| `.look <yaw> <pitch>` | повернуться (градусы как в F3) |
| `.turn <Δyaw> [Δpitch]` | повернуться относительно текущего взгляда (+ вправо / вниз) |
| `.lookat <x y z \| ник>` | посмотреть на точку или игрока |
| `.dialog` | показать текущий диалог сервера |
| `.dialog <№\|текст кнопки>` | нажать кнопку: `.dialog 1`, `.dialog да`, `.dialog confirm` |
| `.dialog set <поле> <значение>` | заполнить поле перед нажатием: `.dialog set name Вася`, `.dialog set agree да` |
| `.dialog close` | закрыть, как Esc в игре (если сервер разрешает) |
| `.gui` | показать открытое меню |
| `.gui click <№\|текст> [right\|shift]` | кликнуть слот по номеру, имени или описанию: `.gui click 11`, `.gui click принять`, `.gui click зеленое стекло` |
| `.gui close` | закрыть меню |
| `.equip <предмет> [hand\|off-hand\|head\|torso\|legs\|feet]` | взять/надеть |
| `.drop [предмет\|all] [кол-во]` | выбросить (без аргументов — то, что в руке) |
| `.use [stop]` / `.click` | ПКМ предметом / по блоку под прицелом |
| `.eat` | поесть |
| `.attack [ник\|nearest] [удары]` | ударить |
| `.jump` / `.sneak` | прыжок / присесть |
| `.pos` `.status` `.inv` `.players` | инфо |
| `.connect` `.disconnect` `.reconnect` | подключение |
| `.respawn` | возродиться |
| `.say <текст>` | написать в чат текст, начинающийся с точки |

`.goto x y z` подстраивает цель под землю: если точка внутри блока, встаёт сверху; если в воздухе
(над листвой, травой, опавшими листьями) — опускается до земли. Если ровно туда не пройти, бот встаёт рядом и пишет,
сколько осталось: `остановился рядом: … — до цели 1.4 бл., по высоте +3`.

В общей консоли можно адресовать конкретных ботов префиксом: `@Bot_01,Bot_02 .goto 0 64 0`.
Команды для экранов тоже работают на всех сразу: `.dialog да` или `.gui click принять` ответит каждому выбранному боту.

`.gui click` с текстом ищет по имени предмета, его описанию и ID. Русские цвета и слова понимаются:
«зеленое стекло» найдёт `lime_stained_glass_pane`, «красная шерсть» — `red_wool`.

## Как бот себя ведёт

- Ходит только через физику mineflayer + pathfinder (клавиши вперёд/прыжок/спринт, гравитация, коллизии).
  Никаких пакетов-телепортов: сквозь блоки бот не ходит.
- Pathfinder по дороге **ничего не ломает и не ставит**, столбы не строит.
- Ломает только в радиусе 4.5 блока (survival reach) и только то, что видит. Если блок далеко, сначала
  подходит туда, откуда его видно. Время копания ванильное (инструмент, эффективность, haste, вода, в воздухе).
  Лучший инструмент берёт сам.
- Бьёт только вплотную (3 блока), с кулдауном.
- Клики по инвентарю такие же, как у игрока (обычный клик, Shift+клик, цифра над слотом), после них окно закрывается.
- Клиент представляется как `vanilla`.
- Поиск пути не забивает процессор: на всех ботов делится общий бюджет ~24 мс на тик, радиус поиска ограничен.
  Боты работают в отдельном от окна процессе, так что окно не подвисает.

## Что исправлено относительно mineflayer

mineflayer местами шлёт не то, что ванильный клиент. Предиктивные античиты (Grim) это видят и откатывают
или кикают бота. Botify исправляет это у себя, в зависимостях ничего не надо править руками.

**Движение** (`src/vanilla.js`, `src/ticker.js`). Внутри тика пакеты идут в ванильном порядке: `player_input`
с полным набором клавиш → `start/stop_sprinting` → движение → `tick_end`.
- Угол головы в пакете не совпадал с тем, по которому посчитано движение (на пути с поворотами — в 56% тиков,
  расхождение до 73°). mineflayer «догонял» поворот максимум на ~8.6° за тик, а pathfinder поворачивал голову
  уже после расчёта движения, но до отправки пакета. Теперь в пакете ровно тот угол, с которым считался тик.
- Повороты через границу полного оборота отправляются непрерывно (`359° → 361°`, а не `359° → 1°`).
  Принудительный `look(..., true)` раньше сбрасывал число оборотов и давал скачки `AimModulo360`.
  Серверная коррекция устанавливает новую точку отсчёта угла.
- На 1.21.5+ (включая 26.1) малые X/Z скорости обнуляются по общей длине горизонтального вектора.
  Старый расчёт отдельно отбрасывал каждую компоненту меньше `0.003`: это теряло боковую инерцию
  на поворотах и после `.stop`, создавая небольшие ошибки `Simulation`.
  Исправление остаётся на исходном месте расчёта: после течения жидкости, перед прыжком и ускорением.
  Для 1.21.4 и старше сохранено прежнее правило.
- На 1.21.6+ / 26.x бег отправлялся с устаревшим номером действия, и сервер читал его как «прыжок на лошади»,
  то есть вообще не знал, что бот бежит. То же с элитрой.
- Бег объявлялся на тик раньше, чем начинался.
- Атрибут скорости из сервера (`generic.movement_speed`) не совпадал с именем, которое искала физика
  (`minecraft:movement_speed`). Теперь серверная скорость и её модификаторы учитываются, бонус спринта
  применяется один раз. Прогнозы pathfinder работают с копией атрибута и не меняют состояние игрока
  (`src/movement-physics.js`). Спринт в физике и пакетах использует одинаковые условия: движение вперёд,
  без встречного ввода/приседания, достаточно еды (кроме creative/spectator).
- После сильного горизонтального столкновения спринт отключается перед следующим движением,
  и физика использует скорость ходьбы. При удержании клавиши бег возобновляется после выхода от стены.
  На 1.18+ лёгкое скольжение вдоль стены (угол менее 8° между вводом и фактическим движением) сохраняет бег.
  Это состояние учитывается также в прогнозах pathfinder; ранее его отсутствие вызывало `SprintE`.
- Остановка pathfinder больше не меняет координаты и скорость напрямую. Его исходный `fullStop()`
  обнулял горизонтальную инерцию и сдвигал игрока к центру блока, в том числе при завершении `.goto`.
  Теперь он отпускает клавиши, а оставшееся движение затухает через обычную физику.
- `player_input` уходил только при приседании, причём без остальных клавиш; `tick_end` не отправлялся совсем;
  флаг «упёрся в стену» всегда был `false`.
- Физика тикала через `setInterval(50)`, а в Windows он срабатывает раз в ~62 мс, и пакеты движения шли пачками.
  Теперь физику всех ботов ведёт один метроном в отдельном потоке с частотой 20 тиков в секунду.
  При зависании основного процесса старые уведомления не накапливаются: после паузы нет пачки
  догоняющих пакетов движения. Во время такой паузы бот временно теряет тики.
  Цена: ~15% одного ядра на Windows, сколько бы ботов ни было.
- Отдача (knockback) терялась: на 1.21.9+ скорость из `entity_velocity` ошибочно делилась на 8000
  (`fixLpVec3Velocity` в `src/bots.js`).
- Серверные коррекции позиции на 1.21.2+ содержат собственную скорость и отдельные флаги её относительности.
  Теперь `dx/dy/dz` и поворот сохраняемой скорости обрабатываются отдельно от флагов координат
  (`src/teleport-motion.js`), включая откаты на 26.1.
- При обычной коррекции сохраняются `onGround` и задержка следующего прыжка. Раньше Mineflayer
  сбрасывал их: следующий тик на земле считался как движение в воздухе с меньшим ускорением.
  После повторных коррекций бот мог практически перестать идти. Первый пакет после входа или
  респавна обрабатывается отдельно, без переноса состояния старого игрока.

Для **26.1 и 26.2** расчёты наземного движения дополнительно сверены с кодом клиентов:
точность Java `float`, таблица поворотов, диагональный ввод, трение, прыжок, порядок столкновений,
подъём на плиты, опора на краю и удержание края при приседании. Использование предмета замедляет
ходьбу и учитывается при спринте. Реализация и границы проверки: [docs/walking-26.1.md](docs/walking-26.1.md).
В 26.2 используется отдельный расчёт трения и сопротивления воздуха с учётом новых атрибутов.
Версия «авто» включает нужную ветку после согласования протокола. При появлении в мире лог
`[движение] протокол …; физика vanilla …` показывает фактически включённую реализацию.

При четырёх коррекциях за три секунды во время движения бот прекращает маршрут и отпускает
клавиши. Автоматически продолжать тот же цикл он не будет; для продолжения нужна новая команда.
Последние тики и отправленные пакеты сохраняются в `data/movement/<id>.json` (или в соответствующей
папке `BOTIFY_DATA`). Файл перезаписывается для данного бота, содержит только данные движения,
без авторизации, чата и инвентаря. Его путь появляется в логе. Коррекции при входе, большие
телепортации и коррекции без активного ввода не запускают эту остановку. Это реакция на повторные
коррекции сервера, а не доказательство срабатывания конкретного античита.

Проверки движения: `npm test`. Они запускают установленную физику Mineflayer без подключения к серверу:
сравнивают 23 траектории с отдельным расчётом на Java и проверяют углы, плиты, потолки, края,
скорость, спринт при упоре и скольжении вдоль стены, полный маршрут через pathfinder с остановкой,
инерцию после остановки, повороты через несколько полных оборотов, коррекции позиции на 26.1,
совместимость пакетов на 1.20.4–26.2 и
восстановление метронома после задержки. Это регрессионные проверки, а не подтверждение отсутствия
флагов Grim; для этого нужен прогон на сервере с конкретной версией и настройками античита.

`npm run test:integration` запускает дополнительную проверку через TCP на локальных эмуляторах
26.1 и 26.2: вход, ходьба, подтверждение 12 коррекций, ограничение подробных логов, сводка и
истечение счётчика. Проверяются также запуск HTTP-интерфейса, иконка и офлайн-скин.
Тест использует случайные порты на `127.0.0.1` и отдельные временные данные; пользовательские
аккаунты не загружает. Эмулятор не содержит Grim и не проверяет допустимость движения.

**Диагностика коррекций** (`src/setbacks.js`). В консоли строки `[коррекция]` показывают разницу
между прежней позицией бота и позицией сервера: вперёд, вбок, вверх, с точностью до 0,0001 блока.
Рядом указаны клавиши, скорость, состояние на земле/в воздухе и блоки. После трёх подробных строк
за 5 секунд остальные объединяются в сводку. В карточке бота отображается число коррекций за
последние 10 секунд; оно истекает и без движения. При респавне, смене сервера и отключении
статистика и ожидающие сводки сбрасываются. Первые 3 секунды после входа/респавна пропускаются.
Перемещения более 6 блоков выводятся отдельно как `[перемещение]`.
Пакет не сообщает причину: короткий телепорт командой или плагином тоже может попасть в счётчик.
Это наблюдение за позицией, а не журнал флагов античита или его расчётной ошибки.

**Загрузка иконок** (`src/assets.js`). Вместо загрузки всех моделей и текстур `minecraft-assets`
при старте читается только таблица текстур нужной версии, по первому запросу. Дополнительные
версии читаются лишь при отсутствии предмета; результат кэшируется. Офлайн-скины не загружают
таблицы иконок.

**Копание:** при копании без поворота головы mineflayer всегда сообщал грань «верх». Теперь уходит та грань,
на которую смотрит прицел (`src/commands.js`).
Перед START бот ждёт отправки окончательного угла головы. Прогресс разрушения накапливается
по `physicsTick`, а не настенному таймеру: пауза процесса больше не заканчивает копание досрочно
относительно отправленных тиков. Для каждого тика заново берётся неокруглённый урон блока с учётом
инструмента, эффектов, воды и состояния на земле. При смене инструмента или уходе прицела с блока
копание отменяется. ABORT при отпускании использует грань DOWN и sequence 0; START/STOP,
использование предметов и установка блоков используют общий возрастающий счётчик `sequence`
на версиях протокола с этим полем.
Продолжение и завершение копания сопровождаются взмахом руки в том же тике: прежний интервал 350 мс
оставлял промежутки между взмахами. При мгновенном разрушении, в том числе
в creative, отправляется начало со взмахом, без лишнего пакета завершения survival-копания.
Блок больше не заменяется воздухом локально: «готово» появляется после серверного обновления блока.
Если после завершения сервер не подтвердил разрушение за 5 секунд, команда сообщает об ошибке.
Отмена, отключение и смена сервера освобождают ожидание и таймеры.
Отключение и смена сервера без активного копания также безопасны: обработчик не передаёт
ошибку в исходный `stopDigging`, который в этом состоянии её выбрасывает.

Порядок действий сверялся с методами `startDestroyBlock`, `continueDestroyBlock`, `stopDestroyBlock`
в `MultiPlayerGameMode` и `continueAttack` в `Minecraft` из локального ванильного клиента 26.2;
пакеты проверяются на эмуляторах 26.1 и 26.2. Связь взмаха и границы тика также сверена с
[NoSwingBreak](https://github.com/GrimAnticheat/Grim/blob/2.0/common/src/main/java/ac/grim/grimac/checks/impl/breaking/NoSwingBreak.java).
Это не полная реализация всех механик клиента: серверные изменения скорости копания и особые
предметы по-прежнему зависят от поддержки в PrismarineJS. Локальный эмулятор не запускает Grim.

**Плавный поворот головы** (`src/smooth-look.js`). В обычном режиме с метрономом повороты
pathfinder, `.follow`, ручных команд и наведения на блок проходят через один контроллер.
Он плавно разгоняет и замедляет поворот. Для ходьбы предел — примерно 9° по горизонтали и 4°
по вертикали за тик; небольшое изменение направления не вызывает постоянного доведения головы.
Наведение на блок остаётся точным, с прежними пределами 12°/8°. Переход через ±180° идёт по короткой
дуге. Физика и пакет движения используют один и тот же промежуточный угол. В прямом преследовании
бот может двигаться по диагонали во время поворота; если цель сзади, сначала разворачивается.
На сложных участках pathfinder по-прежнему ждёт безопасного направления. `.stop`, смерть и серверная коррекция
отменяют старую цель поворота. Наведение завершается после отправки угла, чтобы копание не
начиналось с прежним направлением взгляда на сервере.

**Следование:** `.follow Nick` на свободной ровной площадке бежит прямо к игроку по произвольной
диагонали, без посещения центров каждого блока. При повороте использует также W+A/W+D. Перед прямым
движением проверяются проход для всего тела, опора под ногами и ближайшие тики физики с текущим
углом головы. Стены, ступени, вода, края и незагруженные участки передаются обычному поиску пути;
на маршрутах включено сокращение проверенных прямых участков. Это не гарантия глобально кратчайшего
маршрута на любом рельефе. Голова смотрит вдоль движения, а не постоянно точно в голову игрока.
Рядом с целью бот тормозит; небольшие перемещения игрока не заставляют его дёргаться на месте.
Можно задать дистанцию, например `.follow Nick 3`. Ник ищется без учёта регистра; игрок должен быть
виден боту. `.stop` прекращает следование. Если игрок исчезает из вида, бот умирает, меняет мир или отключается,
задача завершается и её обработчики удаляются.

`.follow Nick spin` включает плавное вращение головы с переключением W/A/S/D относительно
текущего взгляда. Дистанция задаётся как `.follow Nick 3 spin` или `.follow Nick spin 3`.
Скорость задаётся в градусах в секунду: `.follow Nick 3 spin speed=180` — один оборот за 2 секунды
после плавного разгона. Диапазон 1–720°/с, по умолчанию 120°/с (оборот за 3 секунды).
Вращение продолжается при ожидании рядом, поиске/перестроении пути, обходе препятствий и прыжках.
Если путь не найден, бот стоит и продолжает вращаться. Pathfinder выбирает маршрут, а W/A/S/D
пересчитываются под текущий угол перед каждым шагом физики. Сложные обходы и прыжки выполняются
шагом; на прямом участке спринт используется только с допустимым вводом вперёд.
На очень малых скоростях угол накапливается до очередного шага мыши 0,15°.
`.stop`, потеря цели и завершение
задачи прекращают вращение. Для режима нужен включённый контроллер движения и плавного поворота.

`.circle Nick` заставляет бота ходить вокруг игрока с радиусом 3 блока.
`.circle Nick 4 spin speed=180` задаёт радиус 4 блока и непрерывный spin 180°/с.
Радиус — число от 1 блока; `speed` меняет скорость головы, а движение по окружности
идёт обычным шагом. Центр круга следует за игроком, издалека бот сначала подходит.
При препятствиях используются свободные точки окружности и обход через pathfinder,
поэтому радиус на обходе может отклоняться. Без `spin` голова плавно поворачивается по ходу движения.
Остановка и потеря цели обрабатываются так же, как у `.follow`.
Команда из общей консоли применяется ко всем выбранным ботам.
Боты вокруг одного игрока с одинаковым радиусом автоматически распределяются по окружности:
два занимают противоположные стороны, три — места примерно через 120°, четыре — через 90°.
Если впереди тесно, бот отпускает клавиши движения, чтобы освободить место; spin продолжается.
Распределение происходит постепенно и восстанавливается после добавления/выхода участника.
При препятствиях интервалы могут временно отличаться. Группы разделены по серверу, измерению,
целевому игроку и радиусу; новые параметры команды для этого не нужны.

**Команды** (`src/chatfix.js`): minecraft-protocol отправлял любую команду подписанной, если у аккаунта есть ключи
чата, даже `/tpa ник`. Ванильный клиент подписывает только команды с текстом сообщения (`/msg`, `/me`), остальные
шлёт обычными. Серверы и прокси могут молча отбрасывать «неправильные» подписанные пакеты.

**Подключение и HTTP 429.** Запрос определения версии сохраняет исходный адрес сервера после SRV:
соединение идёт на найденный узел, но имя в пакете остаётся тем же, что при входе.
Если сервер всё равно закрывает запрос статуса, можно выбрать известную версию вручную вместо «авто».
Ответ HTTP 429 от авторизации приостанавливает новые подключения онлайн-аккаунтов в текущем
процессе минимум на 30 секунд. Более долгий `Retry-After` также учитывается. Ручное переподключение
не сбрасывает паузу; офлайн-аккаунты её не используют. Это задержка повторной попытки, а не
гарантия, что сервис снимет ограничение за 30 секунд. При выключенном автопереподключении
новая попытка сама не запускается. Пауза не сохраняется после полного перезапуска приложения.
Ответ авторизации, пришедший после отмены подключения или ошибки определения версии,
больше не открывает старое соединение. Патч `scripts/patch-login.js` применяется при установке
и перед загрузкой ботов; он также сохраняет HTTP 429 и `Retry-After` при пустом или HTML-ответе
сервиса сессий. Проверки входят в `npm test` и `npm run test:integration`.

**Патчи зависимостей** (`scripts/patch-26.2.js`, запускается сам на `npm install`):
- поддержка 26.2: данные с зафиксированного коммита PR PrismarineJS (minecraft-data#1344,
  node-minecraft-protocol#1550, mineflayer#4192) и версия в minecraft-data, minecraft-protocol, mineflayer,
  prismarine-chunk, prismarine-physics. По этим PR менять нужно только данные;
- запись встроенного значения реестра (`registryEntryHolder`) в minecraft-protocol пропускала нулевой байт,
  и в пакет попадал мусор. Задевает клики по предметам с некоторыми компонентами;
- описание пакета ответа на диалог (`custom_click_action`, 1.21.6+) в minecraft-data не совпадало с ванильным.
  Без исправления сервер кикает: `Failed to decode packet 'serverbound/minecraft:custom_click_action'`.

Когда PrismarineJS выпустит 26.2 и эти исправления, соответствующие части скрипта можно убрать.

`scripts/patch-physics.js` исправляет порог малой скорости в `prismarine-physics`.
Он автоматически запускается при установке и перед загрузкой ботов, поэтому достаточно полностью
перезапустить Botify. Повторное применение ничего не меняет. Если после обновления зависимости исходный
участок изменился, скрипт сообщает об этом вместо изменения неизвестного кода.
Правило для современных версий сверено с [applyMovementThreshold в Grim](https://github.com/GrimAnticheat/Grim/blob/2.0/common/src/main/java/ac/grim/grimac/predictionengine/predictions/PredictionEngine.java);
проверка скачков угла — с [AimModulo360](https://github.com/GrimAnticheat/Grim/blob/2.0/common/src/main/java/ac/grim/grimac/checks/impl/aim/AimModulo360.java).

`scripts/patch-pathfinder.js` удаляет принудительную остановку скорости и сдвиг к центру блока из
`mineflayer-pathfinder.fullStop()`. Он также применяется при установке и перед загрузкой ботов;
ручное изменение `node_modules` не требуется.

`scripts/patch-digging.js` исправляет взмах при завершении копания и ожидание подтверждения сервера
в плагине Mineflayer. Он применяется при установке и перед загрузкой ботов. Проверки копания и
следования входят в `npm test`; подтверждение отсутствия флагов на живом сервере всё ещё требует
прогона на этом сервере.

## Ферма деревьев 2×2

Поставь бота рядом с приподнятой площадкой из четырёх блоков земли 2×2 и наведи прицел на любой её блок,
в том числе на боковую грань. Изолированный квадрат на одной высоте распознаётся автоматически;
саженцы ставятся сверху, окружающий нижний пол в площадку не входит.
На сплошном ровном поле наведи прицел на угол с меньшими X и Z: там квадрат продолжается по +X и +Z.
Все четыре места должны быть в досягаемости.
В инвентаре нужны Shard Axe, саженцы одного вида и костная мука.
Ферма закрепляет за ними разные слоты хотбара: уже лежащий там топор остаётся на месте.
Недостающие предметы переносит в отдельные слоты при подготовке или пополнении.
В самом цикле переключает выбранный слот и проверяет предмет через один тик; перед копанием
повторно проверяет топор после поворота головы. Обычная смена не открывает инвентарь.

```
.tree farm spruce
.stop
```

Поддерживаются `spruce`, `jungle`, `dark_oak`, `pale_oak`. Можно написать просто `.tree farm`, если нужный
вид однозначен по уже растущим саженцам, предмету в руке или единственному подходящему виду в инвентаре.

Бот сажает от дальнего места к ближнему, проверяет видимость верхней грани земли и ждёт подтверждения
каждой посадки. Затем наводится на ближайший видимый саженец и применяет костную муку, как при
удержании ПКМ: раз в 4 игровых тика, пока сервер не подтвердит появление ствола. Сразу прекращает
взращивание, переключается на топор, рубит стволы внутри выбранной площадки и снова сажает.
При нехватке саженцев или костной муки ждёт пополнения (естественный рост тоже распознаётся).
При препятствии ждёт свободного места, не разбирая механизм. Площадка фиксируется на время команды.
При повторном запуске рядом с прежней площадкой может использовать её сохранённые координаты,
если землю закрыла листва. Без сохранённого выбора распознаёт единственную изолированную площадку
2×2 в досягаемости; при нескольких вариантах нужно указать площадку прицелом.
Листву выбранного вида перед землёй, саженцами и на месте посадки убирает топором, затем продолжает цикл.
Если выросшая листва мешает встать, сначала расчищает пространство над головой. При ползании
прицел рассчитывается с высоты глаз 0,4 блока по позе от сервера. Затем бот продолжает рубку;
естественную листву выбранного вида, перекрывающую ствол, тоже может убрать. Блоки механизма
и поставленную игроком листву не разбирает.
При сбое перекладывания предмета делает ещё 5 попыток с паузами, заново проверяя инвентарь,
и останавливает ферму, если ни одна не удалась. `.stop` отменяет и эти повторы.
В чате Botify появляются предупреждения о неподтверждённой посадке, возврате блока при копании
и проблемах взращивания. Для муки отдельно проверяется передача пакета в транспорт: если её нет
5 секунд, ферма останавливается. Если применения отправляются, но роста нет 10 секунд, бот сообщает
об этом и продолжает (следующие такие сообщения — не чаще раза в 30 секунд).
Эти признаки не доказывают флаг античита: причиной могут быть задержка, защита или условия роста.

В `.tree` и `.tree farm` повороты используют более быстрый плавный профиль с изменяемой длительностью,
небольшой дугой и точной остановкой. Точки прицеливания и короткие паузы выбираются случайно;
порядок дальних и ближних посадок сохраняется. `.stop` отменяет ожидание и дальнейшие действия.

Прежние `.tree` и `.tree any` остаются режимами рубки без посадки.

### Полная автоферма

Во вкладке **Автоферма** настраиваются вид саженцев, радиус поиска (4–64 блока), запас предметов,
метки контейнеров, автолив и общий список друзей. Настройки сохраняются локально и используются
всеми ботами. Кнопка «Сохранить и запустить» запускает выбранного подключённого бота; из его чата
достаточно команды `.autotree` (также `.autotreefarm`). `.stop` отменяет цикл, поход и работу с контейнером.

Бот ищет ближайшую доступную изолированную площадку из четырёх блоков земли, подзола или грязи
квадратом 2×2 на одной высоте; смешанные типы грунта допустимы. Он подходит к свободному месту
рядом с ней без разрушения или установки блоков по пути. Поиск ограничен загруженными чанками
и заданным радиусом. Большое сплошное поле земли не считается отдельной площадкой.

Для запасов поставьте табличку **на контейнер** (настенную — лицом наружу) либо непосредственно рядом:

| Строка таблички по умолчанию | Предмет |
| --- | --- |
| `1` | Костная мука |
| `2` | Бутылочки опыта |
| `3` | Саженцы выбранного вида |

Метка должна совпадать с целой строкой на любой стороне таблички. Настенная табличка обозначает
контейнер, к которому прикреплена; для отдельно стоящей требуется единственный соседний контейнер.
Поддерживаются обычные и ловушечные сундуки, эндер-сундуки, бочки, шалкеры всех цветов, воронки,
раздатчики и выбрасыватели. Бот открывает видимую грань, забирает только заданный предмет до
настроенного количества и возвращается на рабочее место. Стаки нужного предмета выбираются в случайном
порядке; перед первым кликом и между кликами есть случайные паузы 200–400 мс. Целый стак забирается
одним Shift-кликом, остаток при переносе части стака возвращается в исходный слот.
Пустой, недоступный контейнер или полный
инвентарь отражаются в чате. `.autotree` и `.tree farm` автоматически выбрасывают брёвна выращиваемой
породы и палки целыми стаками, сохраняя топор, саженцы, костную муку и остальные предметы. Очистка идёт
при запуске и регулярно между действиями фермы; перед пополнением `.autotree` также освобождает
инвентарь. Бот выбирает ровный свободный пол сбоку от площадки: справа, а если там занято — слева.
Проверяет поверхность вокруг точки, свободный путь без контейнеров и заново наводится перед каждым
стаком. Перед выбросом проверяется фактическое направление взгляда; при смещении или перекрытии
прицела выброс отменяется. Если по бокам нет подходящего пола, выброс откладывается.
Между действиями бот выдерживает паузы не меньше 200 мс и пишет количество
выброшенного в журнал. Выброс использует взятие стака на курсор, клик за пределами окна и закрытие
инвентаря. При отсутствии уменьшения общего количества брёвен выполняются до пяти повторов,
затем очистка делает паузу на 30 секунд; этот отказ сам по себе не останавливает ферму.
Подбор предметов во время выброса отмечается отдельно. `.stop` прекращает очистку. Опыт только запасается,
автоматической починки ещё нет; запас опыта `0` отключает его получение.

В разделе **Автоферма → Уведомления Discord** можно включить общий вебхук для всех ботов,
вставить его URL и нажать **Сохранить и проверить Discord**. Настройки сохраняются локально;
пока уведомления выключены или ссылка не указана, отправок нет. В сообщение входят ник, сервер,
время и причина: кик/возможный бан с текстом сервера, отключение (включая ручное), автолив, смерть,
ошибка фермы и повторяющиеся коррекции/сбои действий. О нехватке расходников уведомление приходит
только после открытия контейнера, если нужного предмета в нём нет. Пустой инвентарь бота,
ненайденная табличка, недоступный контейнер и ошибка переноса сами по себе такого уведомления не вызывают.
Коррекции не объявляются подтверждённым флагом античита. Порог предупреждения о прочности Shard Axe
настраивается в процентах, по умолчанию 10%; уведомление не останавливает работу и не чинит топор.
Одинаковая проблема у одного бота повторяется не чаще раза в пять минут. Ошибки доставки видны
в локальном журнале; отправки идут последовательно, с таймаутом и ограниченными повторами.
Приложение должно оставаться запущенным и иметь доступ к Discord.

Автолив включён по умолчанию для `.autotree` и `.tree farm`: при появлении постороннего игрока
в загруженной области бот отменяет работу и отключается, **без автоматического переподключения**.
Уже стоящий рядом игрок тоже учитывается. Друзья и другие подключённые боты этого приложения
игнорируются. Для следующего входа нужна ручная команда подключения. Времени на спасение от
уже нанесённого удара эта функция не гарантирует.

Общий список друзей (без учёта регистра) можно менять из вкладки или командами любого бота/общей консоли:

```text
.friend add Nick
.friend remove Nick
.friend list
.friend clear
```

Все боты учитывают изменения сразу: друзей не атакуют и не считают причиной автолива.

## Где что лежит

Всё локально, обычный JSON, без шифрования, в папке `data/`:

```
data/settings.json      глобальный сервер, поведение, тема
data/accounts.json      боты + их токены
data/auth-cache/<id>/   кэш входа Microsoft (prismarine-auth)
data/cache/skins/       скачанные скины для аватарок
```

`accounts.json`:

```json
{
  "version": 1,
  "accounts": [
    { "id": "b_1a2b3c4d5e", "type": "offline", "username": "Bot_01", "server": null },
    { "id": "b_…", "type": "refresh", "username": "Nick", "uuid": "…",
      "refreshToken": "M.C5…", "clientId": "00000000402b5328",
      "accessToken": "eyJ…", "accessTokenExpiresAt": 1731500000000,
      "server": { "host": "mc.example.com", "port": null, "version": "auto" } }
  ]
}
```

`"server": null` означает глобальный сервер, `"port": null` — 25565 или SRV-запись.

Токены уходят только на сервера Microsoft / Xbox / Mojang и на сервер, куда заходит бот (стандартная проверка сессии).
Интерфейс их вообще не получает. Бэкенд слушает только `127.0.0.1` и отклоняет чужие `Host`/`Origin`,
так что сайты в браузере не могут к нему подключиться. `data/` в `.gitignore`.

## Переменные окружения

| Переменная | Что делает |
|---|---|
| `BOTIFY_DATA` | другая папка для данных вместо `data/` |
| `BOTIFY_PORT` | порт бэкенда вместо 7878 |
| `BOTIFY_NO_TICKER=1` | физика на штатном таймере mineflayer (без точного метронома; тогда отключается и ванильный порядок пакетов в тике) |
| `BOTIFY_NO_VANILLA=1` | без исправлений пакетов движения из `src/vanilla.js` |
| `BOTIFY_NO_CHATFIX=1` | команды отправляются как в minecraft-protocol, без `src/chatfix.js` |

Нужны для диагностики: если что-то сломалось, можно отключить по одной части и посмотреть, в ней ли дело.
В PowerShell: `$env:BOTIFY_NO_VANILLA=1; npm start`.

## Известные проблемы

- **Античиты.** Исправления движения проверены на эмуляторе сервера 26.2: пакеты совпадают с ванильными по
  составу, порядку и углу головы. Против настоящего Grim пока не проверялось.
- **Вход по токенам:** есть сообщение, что импорт токенов не проходит. Пока не разобрано.
- Встроенные в клиент диалоги (например, список ссылок сервера) Botify видит только по названию, без содержимого.
- Если окно не открывается, а в терминале пусто, запусти `npm run web` и открой браузер. Ошибку из терминала стоит сохранить.
# Передача через ордер

`.transfer spruce_log BuyerNick` создаёт у подключённого BuyerNick ордер на сумму выбранного предмета у остальных подключённых ботов на том же сервере. Цена выбирается в диапазоне 5.0–5.9 за предмет. Сервер также может взимать налог.

Текущие задачи участников останавливаются. Каждый продавец сначала сдаёт один предмет; продолжение разрешается только после сообщения покупателю с совпадающими ником, предметом и количеством. Остаток переносится из случайных слотов с паузами 300–700 мс между кликами. Окно сдачи закрывается перед подтверждением, как при Escape. Предметы поступают в ордер покупателя; автоматический сбор из ордера не выполняется.

`.stop` у любого участника останавливает общую передачу. При ошибке повторная сдача автоматически не запускается; созданный ордер может остаться открытым — проверьте Your Orders. Фермы автоматически не возобновляются. В общей консоли команда запускает одну общую операцию.

## Из сундуков: `.transfer spruce_log BuyerNick chests [радиус]`

Покупатель создаёт **один большой ордер** на круглое случайное число 400k–600k (например, 512k) по цене 5.0–5.9 — его легко узнать в списке. Сундуки размечаются двумя табличками с текстом `start` и `end` (по одной, в радиусе поиска от продавца — по умолчанию 24, от 4 до 64). Используются только сундуки, бочки и сундуки-ловушки в прямоугольнике между табличками и блоками, на которых они висят; обход идёт от `start` к `end`, сверху вниз в каждом столбце. Без табличек ордер не создаётся. Ордер ищется через `/orders <ник покупателя>`; если команда не работает — через общий список. Продавец сначала сдаёт то, что у него в инвентаре, затем ходит к сундукам, набирает полный инвентарь выбранного предмета случайными целыми стаками, сдаёт его в ордер и идёт за следующей партией, пока предмет в сундуках не кончится. Другие предметы из сундуков не берутся. Двойной сундук считается одним контейнером.

Сундуки, в которых выбранного предмета не осталось, запоминаются в `data/transfer-chests.json` отдельно для каждой стены (сервер, предмет, координаты табличек) и при следующих запусках пропускаются. Сундук, который не удалось открыть, пропускается только в текущем запуске. Если сундуки снова наполнили — `.transfer spruce_log BuyerNick chests reset`.

Ордер остаётся открытым на несдатый остаток — отмените его в Your Orders, чтобы вернуть деньги. Покупатель должен иметь деньги на весь ордер при создании; если сервер не ответил `You ordered …`, передача останавливается.
